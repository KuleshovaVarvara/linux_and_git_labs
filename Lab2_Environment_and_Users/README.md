## Задание 1. Локальные и глобальные переменные среды

**Условие:**
1. Просмотрите существующие в системе глобальные переменные и переменные оболочки одной командой.
2. Добавьте локальную переменную `MY_LOCAL_VAR` со значением `local_var_value`. Откройте новое окно терминала и проверьте наличие переменной.
3. Через `.bashrc` создайте переменную оболочки `MY_SHELL_VAR` со значением `shell_var_value`. Убедитесь, что она доступна в любом окне терминала.
4. Через `/etc/environment` создайте глобальную переменную `MY_GLOBAL_VAR` со значением `global_var_value`. Проверьте её в новом окне терминала и через Python.

<details>
<summary><b>Показать решение</b></summary>

### 1) Просмотр переменных

```bash
set
```

### 2) Локальная переменная

```bash
MY_LOCAL_VAR="local_var_value"
echo $MY_LOCAL_VAR
```

В новом окне терминала:

```bash
echo $MY_LOCAL_VAR
# пустой вывод — переменная локальная, в новой сессии не видна
```

### 3) Переменная оболочки через `.bashrc`

```bash
echo 'MY_SHELL_VAR="shell_var_value"' >> ~/.bashrc
source ~/.bashrc
echo $MY_SHELL_VAR
```

Проверка в новом окне терминала:

```bash
echo $MY_SHELL_VAR
# shell_var_value
```

### 4) Глобальная переменная через `/etc/environment`

```bash
sudo nano /etc/environment
```

Добавить в конец файла строку:

```text
MY_GLOBAL_VAR="global_var_value"
```

Сохранить (`Ctrl+O`, `Enter`, `Ctrl+X`). Проверить содержимое:

```bash
cat /etc/environment
```

Перезагрузить систему (изменения в `/etc/environment` применяются после перелогина/перезагрузки):

```bash
sudo reboot
```

После перезагрузки в новом окне терминала:

```bash
echo $MY_GLOBAL_VAR
python3 -c 'import os; print(os.getenv("MY_GLOBAL_VAR"))'
```

## Задание 2. Пользователи, группы и права доступа

**Условие:**
1. Вывести все группы текущего пользователя.
2. Создать группу `new_group` с произвольным паролем, новую директорию и файл `test_file.txt` внутри неё с произвольной информацией.
3. Запретить чтение/запись/исполнение файла `test_file.txt` для всех остальных пользователей. Изменить группу файла на `new_group`, владельца — на `root`.
4. Попробовать записать новую информацию в файл. Добавить текущего пользователя в группу `new_group` и дописать в конец файла строку `User currently in the group`.

<details>
<summary><b>Показать решение</b></summary>

### 1) Группы текущего пользователя

```bash
groups
```

### 2) Создание группы, директории и файла

```bash
sudo groupadd -p new_group1 new_group
sudo gpasswd new_group        # задать произвольный пароль
mkdir test_dir
echo "some information" > test_dir/test_file.txt
```

### 3) Права доступа, владелец и группа

```bash
# запрет на rwx для остальных (маска 750: rwxr-x---)
chmod 750 test_dir/test_file.txt

# смена группы
sudo chgrp new_group test_dir/test_file.txt

# смена владельца
sudo chown root test_dir/test_file.txt
```

Проверка:

```bash
ls -l test_dir/test_file.txt
# -rwxr-x--- root new_group ... test_file.txt
```

### 4) Попытка записи и добавление в группу

Попытка записи от текущего пользователя (ожидается отказ):

```bash
echo "new info" >> test_dir/test_file.txt
# bash: test_dir/test_file.txt: Permission denied
```

Даём группе право записи и добавляем пользователя в группу:

```bash
sudo chmod 770 test_dir/test_file.txt
sudo usermod -aG new_group $USER
newgrp new_group
echo "User currently in the group" >> test_dir/test_file.txt
```

</details>

## Задание 3. Символические ссылки и псевдонимы

**Условие:**
1. Создать символическую ссылку `tf` на файл `test_file.txt` в директории из `$PATH`. Запретить чтение/запись/исполнение ссылки для группы и остальных. Изменить владельца файла на `root`. Проверить, сохранился ли доступ к файлу по ссылке и напрямую.
2. Создать псевдоним `lr`, эквивалентный `ls -l`. Проверить работу. Закрыть окно терминала и попробовать применить снова. Через `.bashrc` обеспечить доступность псевдонима в любом окне.

<details>
<summary><b>Показать решение</b></summary>

### 1) Символическая ссылка

```bash
sudo ln -s /home/$USER/test_dir/test_file.txt /usr/local/bin/tf
sudo chown -h root /usr/local/bin/tf
```

Проверка:

```bash
ls -l /usr/local/bin/tf
tf
```

**Вывод:** по символической ссылке доступ также ограничен правами целевого файла. Если у текущего пользователя нет прав на чтение самого `test_file.txt`, то и через ссылку доступа не будет — символическая ссылка не меняет права доступа целевого файла. Прямой доступ к файлу также отсутствует, если у пользователя нет соответствующих прав.

### 2) Псевдоним `lr`

Временный псевдоним (действует только в текущей сессии):

```bash
alias lr='ls -l'
lr
```

После закрытия окна терминала псевдоним исчезнет. Чтобы сделать его постоянным:

```bash
echo "alias lr='ls -l'" >> ~/.bashrc
source ~/.bashrc
lr
```

Теперь псевдоним доступен в любом новом окне терминала.

</details>

## Задание 4. Управление процессами. Мультиплексоры

**Условие:**
1. Просмотреть список активных задач. Запустить произвольную задачу в фоне. Отложить выполнение произвольной задачи, затем возобновить её с передачей управления на активный терминал.
2. Используя `tmux`, создать две сессии. В первой выполнить `cat`, во второй — `echo "the second session"`. Подключиться к первой, остановить `cat`, отключиться и завершить сессию. Закрыть окно терминала. В новом окне подключиться ко второй сессии и выполнить произвольную команду.

<details>
<summary><b>Показать решение</b></summary>

### 1) Управление задачами

```bash
# список активных задач
jobs

# запуск в фоне
sleep 100 &

# просмотр задач
jobs

# запуск на переднем плане и приостановка (Ctrl+Z)
sleep 200
# Ctrl+Z

# возобновление с передачей управления терминалу
fg %2
```

### 2) Работа с tmux

**Создание двух сессий:**

```bash
tmux new -s session1
```

В первой сессии выполнить `cat`, затем отключиться: `Ctrl+B`, `D`.

```bash
tmux new -s session2
echo "the second session"
```

Отключиться: `Ctrl+B`, `D`.

**Подключиться к первой сессии и остановить `cat`:**

```bash
tmux attach -t session1
# Ctrl+C — остановить cat
# Ctrl+B, D — отключиться
```

**Завершить первую сессию:**

```bash
tmux kill-session -t session1
```

Закрыть текущее окно терминала, открыть новое и подключиться ко второй сессии:

```bash
tmux attach -t session2
# выполнить произвольную команду, например:
ls -la
```

</details>
